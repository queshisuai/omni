# SeatCraft 座位图集成设计

## 背景

`seatcraft` 是一个独立的 React 座位图设计与选座工具，支持设计模式和选座模式、演出场地/影院/自定义模板、方阵和圆弧布局、舞台和分区拖拽、核心优选区、缩放平移以及分区颜色展示。

当前主站已经有场馆区域、座位模板、场次座位快照、选座下单和订单锁座能力，但前端座位图仍是简单网格，后台配置也缺少 SeatCraft 这种可视化布局和模板化起步能力。

本设计目标是把 SeatCraft 的布局能力并入主站：后台在创建活动或场次时可以用模板快速创建座位图，再按活动或场次实际情况修改分区、排数、座数和样式；C 端购票时使用同一套布局渲染真实座位状态并完成选座下单。

## 目标

- 场馆下提供 SeatCraft 基础模板库，至少包含演出场地、影院模式、自定义三类起点。
- admin 和 organizer 创建活动时可以选择座位图配置方式。
- 支持活动统一座位图，也支持每个场次独立座位图。
- 活动或场次座位图从模板复制后独立保存，后续修改不影响公共模板。
- SeatCraft 分区自动生成票档草稿，一个分区对应一个票档。
- C 端按场次最终座位图展示座位，按票档限制可选分区。
- 后端继续以 `session_seat` 快照作为锁座、售出、下单的事实来源。
- 有订单或锁座后只允许安全修改，避免破坏已交易座位。

## 非目标

- 第一版不做逐个座位自由拖拽和逐座坐标持久化。
- 第一版不允许 organizer 修改公共场馆模板，只允许从模板复制后编辑自己的活动或场次座位图。
- 第一版不做座位级独立定价；价格仍由分区生成的票档决定。
- 第一版不把 SeatCraft 作为独立外部工具导入 JSON，而是并入主站后台流程。

## 核心概念

### SeatCraft 模板

场馆下的快捷模板，只作为创建座位图的起点。模板包括舞台配置和分区配置，例如演出场地、影院模式、自定义。

模板被复制到活动或场次后，活动/场次拥有独立副本。修改副本不会影响模板。

### 活动默认座位图

活动自己的默认座位图配置。活动选择统一座位图时创建，用于该活动下多个场次复用。创建场次时可以直接复制活动默认座位图，也可以复制后为某个场次单独编辑。

### 场次座位图

某个场次最终使用的座位图配置。C 端购票只读取场次座位图。场次座位图可以从活动默认座位图复制，也可以直接从场馆模板创建。

### 座位快照

`session_seat` 是真实可售座位快照，用于锁座、支付、订单、退款。前端渲染和后端下单都必须以该快照为事实来源，不能只依赖临时计算出的布局。

## 后台流程

### 场馆模板库

场馆下维护基础模板库：

- 演出场地：默认包含池座内场和环绕看台，支持圆弧看台。
- 影院模式：默认包含观影大厅和核心优选区。
- 自定义：只有舞台，无分区，用于从零开始设计。

admin 可以维护公共场馆模板。organizer 创建活动或场次时可以选择模板作为起点，但不直接修改公共模板。

### 创建活动

创建活动时增加座位图配置方式：

- 统一座位图：选择场馆模板，进入 SeatCraft 设计器编辑活动默认座位图。后续创建场次时默认复制这套活动座位图。
- 每场单独配置：活动创建时不生成最终座位图。创建每个场次时单独选择模板并编辑。

活动使用统一座位图时，仍允许某个场次选择“复制并编辑本场座位图”，用于加排、加区、封区或特殊舞台布置。

### 创建或编辑场次

场次保存前必须拥有最终场次座位图。

如果活动是统一座位图：

- 默认复制活动默认座位图生成场次座位图。
- 可选择复制后编辑本场座位图。

如果活动是每场单独配置：

- 创建场次时选择场馆模板。
- 进入 SeatCraft 设计器编辑本场座位图。

保存场次座位图后，系统按分区生成票档草稿：

- 一个分区对应一个票档草稿。
- 票档名称默认等于分区名称。
- 库存默认等于该分区可生成座位数。
- admin 或 organizer 填写价格，可以调整票档名称和库存。

最终保存场次时：

- 保存场次座位图配置。
- 保存票档。
- 根据分区配置生成 `session_seat` 快照。
- 每个座位记录所属场次分区和对应票档。

## C 端购票流程

用户进入活动详情页后：

- 选择场次。
- 前端加载该场次座位图配置、分区、票档和真实座位状态。
- 用户选择票档后，只允许选择该票档对应分区内的可售座位。
- 其他票档分区可以置灰或不可点击。
- 用户点击座位选中或取消。
- 页面展示已选座位、数量、单价、总价。
- 提交订单时只提交 `sessionSeatIds`，后端根据真实座位和票档计算金额，不信任前端价格。

## 数据模型

### `venue_seat_layout_template`

场馆下的 SeatCraft 基础模板。

建议字段：

- `id`
- `venue_id`
- `name`
- `template_type`：`concert` / `cinema` / `custom`
- `stage_title`
- `stage_x`
- `stage_y`
- `canvas_width`
- `canvas_height`
- `status`
- `create_time`
- `update_time`

### `venue_seat_layout_template_section`

模板分区配置。

建议字段：

- `id`
- `template_id`
- `section_key`
- `name`
- `rows`
- `cols`
- `x`
- `y`
- `color`
- `type`：`core` / `stand` / `zone`
- `layout`：`grid` / `curved`
- `radius`
- `arc_span`
- `rotation`
- `prime_row_start`
- `prime_row_end`
- `prime_col_start`
- `prime_col_end`
- `sort`
- `status`

### `activity_seat_layout`

活动默认座位图。活动选择统一座位图时存在。

建议字段与模板主表基本一致，并增加：

- `activity_id`
- `source_template_id`
- `layout_mode`：可记录活动配置方式，例如 `unified`。

### `activity_seat_layout_section`

活动默认座位图分区。字段与模板分区表一致，并关联 `activity_seat_layout.id`。

### `session_seat_layout`

场次最终座位图。C 端渲染和场次座位生成以它为准。

建议字段与模板主表基本一致，并增加：

- `session_id`
- `activity_layout_id`
- `source_template_id`
- `locked` 或 `has_trade_snapshot`：可选缓存字段，用于后台提示是否已有交易保护。

### `session_seat_layout_section`

场次最终分区配置。每个分区后续绑定一个票档。

建议字段与模板分区表一致，并增加：

- `session_layout_id`
- `ticket_type_id`
- `seat_count`

### `session_seat`

继续作为真实座位快照。建议补充：

- `layout_section_id`：关联 `session_seat_layout_section.id`。

保留现有交易字段：

- `ticket_type_id`
- `status`
- `lock_expire_time`
- `order_id`

## SeatCraft 布局生成规则

后端和前端需要使用一致的分区生成规则。

### 方阵布局

- 按 `rows` 和 `cols` 生成固定行列座位。
- 行号从 1 开始。
- 座号从 1 开始。
- 座位标签默认是 `{row}排{col}座`。

### 圆弧布局

- 按 `rows`、`cols`、`radius`、`arc_span` 生成弧形分布。
- 第一版可以保持每一排相同座位数，降低后端座位数量与库存计算复杂度。
- 如果后续要完全复刻 SeatCraft 当前“外排按弧长增加座位”的算法，需要在设计器保存每排最终座位数，并在后端明确生成规则。

### 优选区

- `primeRange` 只影响展示高亮，不直接决定价格。
- 价格仍由分区绑定票档决定。

## 安全修改规则

如果场次没有锁座、订单、售出座位：

- 允许任意修改座位图。
- 修改后可以重建票档和 `session_seat` 快照。

如果场次已有锁座、订单或售出座位：

- 允许修改视觉类配置：分区名称、颜色、舞台标题、舞台位置、分区位置、旋转。
- 允许新增分区、新增排、新增座位。
- 允许调整弧形半径和跨度，但不能导致已有已锁、已售或已下单座位消失。
- 不允许删除包含已锁、已售或已下单座位的分区。
- 不允许减少包含已锁、已售或已下单座位的行列范围。
- 不允许改变已交易座位对应的票档。

如果修改会破坏已交易座位，后台提示：该场次已有订单或锁座，请复制为新场次或仅做安全修改。

## 前端组件设计

将 `seatcraft/src/components/SeatMap` 并入主站并拆成两个面向业务的组件。

### `SeatLayoutDesigner`

后台设计器组件。

能力：

- 模板初始化。
- 舞台拖拽。
- 分区拖拽。
- 添加、复制、删除分区。
- 编辑分区名称、类型、颜色、布局、行列、旋转、半径、弧形跨度、优选区。
- 一键对齐。
- 保存为活动默认座位图或场次座位图。

### `SeatSelectionMap`

C 端选座组件。

能力：

- 使用场次座位图配置渲染舞台和分区。
- 使用真实 `session_seat` 状态渲染可选、已选、锁定、售罄。
- 支持缩放和平移。
- 选择票档后限制可点击分区。
- 展示图例和已选座位摘要。

## 权限

- admin 可以维护所有场馆模板、活动座位图、场次座位图。
- organizer 可以为自己活动创建和编辑活动座位图、场次座位图。
- organizer 可以从公共场馆模板复制出自己的活动或场次座位图。
- organizer 不直接修改公共场馆模板，避免影响其他活动。

## 兼容和迁移

- 现有 `session_seat` 和订单数据保持不变。
- 现有简单座位模板不立即删除。
- 已有活动或场次可以继续使用旧座位图，或通过迁移转换成 `custom` 类型场次座位图。
- 新功能优先用于新建活动和新建场次。

## 测试策略

- 后端测试模板复制到活动座位图。
- 后端测试模板或活动座位图复制到场次座位图。
- 后端测试分区生成票档草稿。
- 后端测试场次座位快照生成数量和票档绑定。
- 后端测试有订单或锁座时的安全修改限制。
- 前端类型检查覆盖新增 API 类型和组件 props。
- 前端手动验证后台设计器三类模板、分区编辑、保存后 C 端选座渲染。
- 下单回归验证后端只按 `sessionSeatIds` 和真实票档计算金额。

## 实施顺序建议

1. 增加数据库表和后端实体/Mapper。
2. 增加模板初始化和复制服务。
3. 增加活动座位图与场次座位图 API。
4. 增加按分区生成票档草稿和 `session_seat` 快照能力。
5. 将 SeatCraft 组件并入前端并拆出设计器和选座组件。
6. 改造活动创建和场次创建流程。
7. 改造 C 端活动详情页选座图。
8. 补齐安全修改校验和回归测试。
