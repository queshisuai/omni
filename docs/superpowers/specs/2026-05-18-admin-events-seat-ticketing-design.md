# Admin 演出管理与座位票务系统设计

## 目标

把 B 端演出管理和 C 端购票流程从演示型活动库存升级为真实票务模型。系统默认平台演出主要由 admin 上传和管理，admin 拥有最高后台权限；organizer 维持现状，仍可管理自己名下数据。

本设计覆盖后台入口、商户状态一致性、活动/场次/场馆管理、场馆申请、座位模板、票档区域绑定、座位图选座、自动分配、15 分钟锁座、支付成功扣库存、退款后座位恢复规则，以及合理种子数据重建。

## 角色与权限

### admin

- 拥有后台最高权限。
- 可查看、创建、编辑、上下架全部活动。
- 可管理全部场次和平台公共场馆。
- 可审核商户入驻申请和场馆申请。
- 可取消主办方资格，并触发批量下架和真实退款。

### organizer

- 维持现状，可管理自己名下活动和场次。
- 活动归属保持当前逻辑：谁创建，`organizer_id` 就是谁。
- 可提交场馆申请。
- 审核通过的场馆进入平台公共场馆库，不成为私有场馆。

### user

- 可浏览、选座、购票、查看订单。
- 已取消主办方资格的用户点击商户入驻时，可重新提交入驻申请。
- 已取消主办方资格时不显示“当前账号可直接进入商户后台”。

## 前台后台入口

Header 用户菜单按角色展示：

- 未登录：登录、注册。
- 普通用户：个人中心、订单等 C 端入口。
- admin/organizer：显示“进入后台”。

商户入驻页仍保留申请与状态展示：

- 普通用户提交入驻申请。
- 待审核、已驳回、已取消资格用户查看状态并重新申请。
- 已是 organizer 或 admin 的用户可以看到后台入口，但 Header 是主要入口。

## 商户状态一致性

取消主办方资格会更新 `user.role=user` 和 `user.organizer_status=3`。入驻审核页不能只看 `organizer_application.status=1`，还必须展示用户维度状态。

后台入驻审核列表需要展示：

- 申请状态：待审核、已通过、已驳回。
- 账号主办方状态：待审核、已认证、已拒绝、已取消资格。

当 `organizer_status=3` 时：

- 入驻审核页显示“已取消资格”。
- 禁用“取消资格”按钮。
- 商户入驻页允许重新申请，不显示直接进入后台。

## 活动管理

活动管理面向 admin 和 organizer：

- admin 可管理全部活动。
- organizer 只能管理自己名下活动。
- 活动归属保持现有逻辑：谁创建，`organizer_id` 就是谁。

活动列表需要支持：

- 搜索活动名称。
- 按状态筛选：上架、下架、草稿或待完善。
- 分页。
- 加载态、空态、错误态。
- 统一操作反馈。

活动创建和编辑需要校验：

- 活动名称必填。
- 分类、艺人、海报、详情说明按现有数据结构维护。
- 上架前必须至少有一个有效场次、票档和可售座位。

下架活动继续沿用真实退款链路：

- 下架前必须二次确认同意退款。
- 下架活动、场次、票档。
- 对已支付订单走直接支付宝退款。
- 退款结果区分成功、失败、未知、需人工处理。

## 场次管理

场次是活动下的售卖单元。

规则：

- 每个场次属于一个活动。
- 每个场次绑定一个平台公共场馆。
- 结束时间必须晚于开始时间。
- 新建场次不能早于当前时间。
- 同一场馆同一时间段不允许明显冲突。
- admin 可管理全部场次。
- organizer 只能管理自己活动下的场次。

场次列表需要支持：

- 按活动筛选。
- 按场馆筛选。
- 按状态筛选。
- 按时间排序。
- 显示票档数、总座位数、已售数量、余票数量。

## 场馆管理与场馆申请

场馆是平台公共资源。

admin 可：

- 查看公共场馆。
- 创建和编辑场馆。
- 配置场馆座位模板。
- 启用或停用场馆。
- 审核 organizer 提交的场馆申请。

organizer 可提交场馆申请，字段包括：

- 场馆名称。
- 城市。
- 地址。
- 容量。
- 联系人姓名。
- 联系电话。
- 资质编号。
- 经营范围。
- 申请说明或备注。

admin 审核场馆申请时可选择：

- 创建新公共场馆。
- 关联已有公共场馆。

审核通过后，该场馆进入平台公共场馆库，所有主办方创建场次都可选择。驳回必须填写原因。organizer 可查看自己提交的场馆申请状态。

## 座位模板

场馆座位模板由后台表单生成。每个场馆可配置多个区域。

区域字段：

- 区域名称，如 VIP 区、A 区、B 区、看台区。
- 排数。
- 每排座位数。
- 起始排号。
- 起始座号。
- 区域排序。
- 区域颜色。
- 是否启用。

系统根据区域配置自动生成场馆座位。座位字段包括：

- 场馆 ID。
- 区域 ID。
- 排号。
- 座号。
- 展示坐标或排序信息。
- 状态：启用、停用。

场馆座位模板不直接售卖。创建场次后，系统从场馆模板生成一份场次座位售卖快照。

## 票档与座位区域绑定

票档不再随意手动填写库存，而是绑定座位区域。

创建场次票档时：

- 输入票档名称。
- 输入价格。
- 选择一个或多个座位区域。
- 系统自动计算 `totalStock` 为绑定区域可售座位数。
- 系统自动计算 `remainStock` 为未售且未锁的座位数。

约束：

- 同一场次内，一个座位区域不能同时绑定多个票档。
- 票档价格与区域强绑定，避免低价票购买高价区域座位。
- 不允许手动设置超过区域可售座位数的库存。

## 座位图购票流程

活动详情页购票流程升级为：

1. 用户选择场次。
2. 用户选择票档。
3. 系统展示该票档绑定区域的座位图。
4. 用户可手动选座，也可点击自动分配。
5. 用户确认下单。
6. 系统锁定座位 15 分钟。
7. 支付成功后座位变为已售，票档库存扣减。
8. 超时未支付或取消订单后释放座位，库存恢复。

座位图采用仿大麦/影院交互：

- 顶部显示舞台方向。
- 座位按区域分块。
- 支持缩放。
- 支持拖拽。
- 不同颜色展示可选、已选、已锁定、已售、不可售。
- 支持自动分配连续座位。
- 选座区展示已选座位、票价、总价。

## 锁座与库存扣减

座位状态：

- `AVAILABLE`：可售。
- `LOCKED`：已锁定，等待支付。
- `SOLD`：已售。
- `DISABLED`：不可售。
- `REFUNDED_AVAILABLE`：退款后重新可售。
- `REFUNDED_CLOSED`：退款后不可售。

规则：

- 锁座时长为 15 分钟。
- 锁座成功后创建待支付订单。
- 支付成功后订单改为已支付，座位改为已售，票档余票扣减。
- 支付失败、取消订单或超时未支付后释放座位并恢复库存。
- 第一阶段可使用接口触发式释放超时锁座；后续再增加定时任务。

## 退款后座位处理

退款成功后按距离开演时间判断是否重新可售。

规则：

- 距离开演时间大于 24 小时：座位重新变为可售，票档库存恢复。
- 距离开演时间小于或等于 24 小时：座位变为退款关闭，不再二次销售。
- 活动、场次或票档已下架时：座位不重新可售。
- 强制下架退款和取消主办方资格退款：座位不重新可售。

## 订单与座位关系

订单必须记录具体座位。建议新增 `order_seat` 表：

- `id`
- `order_id`
- `session_id`
- `ticket_type_id`
- `seat_id`
- `seat_label`
- `price`
- `status`
- `lock_expire_time`
- `create_time`
- `update_time`

订单金额由选中座位对应票档价格计算，不能只信任前端传来的 `unitPrice`。

## 种子数据重写

重写 seed 数据，避免现有模拟数据中城市、时间段、场馆和票档不合理的问题。

第一版采用中等规模；如果工作量过大，降级为少量精简版。

建议覆盖城市：

- 北京。
- 上海。
- 广州。
- 深圳。
- 成都。
- 杭州。
- 南京。
- 武汉。
- 西安。
- 重庆。

数据要求：

- 每个城市 1 到 2 个高质量场馆。
- 每个场馆配置合理区域和座位模板。
- 每类演出 3 到 5 个活动。
- 每个活动 1 到 3 个未来场次。
- 每个场次绑定真实场馆。
- 每个场次生成票档和座位快照。
- 避免同场馆同时间冲突。
- 票价与区域匹配。

## 分阶段实施

实施计划必须拆成多个可提交任务，而不是一次性完成。

建议阶段：

1. 修复商户状态一致性和前台后台入口。
2. 完善活动、场次、场馆基础管理体验。
3. 实现场馆申请审核闭环。
4. 实现场馆座位模板和场次座位快照。
5. 实现票档绑定区域和库存自动计算。
6. 实现座位图选座、自动分配和 15 分钟锁座。
7. 改造支付成功、取消、退款后的座位和库存流转。
8. 重写合理种子数据。

每个阶段需要包含测试和验证，完成后可独立提交。

## 验收标准

- admin/organizer 可从 Header 用户菜单进入后台。
- 已取消主办方资格的用户可从商户入驻页重新申请，不再看到直接进后台提示。
- 入驻审核页能显示已取消资格状态。
- 活动、场次、场馆管理具备搜索、筛选、分页、表单校验和状态反馈。
- organizer 可提交场馆申请，admin 可审核并创建或关联公共场馆。
- 场馆可通过后台表单生成座位区域和座位模板。
- 场次可生成座位售卖快照。
- 票档绑定区域，库存由区域座位自动计算。
- 用户可手动选座或自动分配座位。
- 下单锁座 15 分钟。
- 支付成功后座位售出且库存扣减。
- 取消或超时后座位释放且库存恢复。
- 退款后按开演时间和下架状态决定座位是否重新可售。
- 种子数据时间、城市、场馆、票档和座位关系合理。
