- 默认密钥：`JWT_SECRET`、`INTERNAL_API_TOKEN`、本地数据库密码和启动脚本默认值。

- 外部依赖：Sentry、PostHog、Alipay sandbox 的默认禁用态和授权边界。

## 结论

阶段 10 已关闭两个会直接扩大认证或账号风险的 P0：grab-service 不再接受缺失 `JWT_SECRET` 时的硬编码默认密钥，`java-user` 不再默认返回或接受固定短信验证码。验证码相关前端默认文案也已改为生产中性提示，不再暴露本地演示说明、本地演示验证码或短信供应商接入状态；登录页未接通的扫码和第三方登录入口已隐藏。`prod-split` 已阻断 Java 服务继承本地 internal token fallback、订单/通知 JWT fallback、RabbitMQ 本地默认值、Nacos/Seata 本地地址 fallback、Gateway 抢票路由本地地址、`java-user` 到 grab-service 的 Feign localhost fallback 和 Alipay sandbox fallback；`java-payment` 基础 profile 不再携带 Alipay sandbox 凭据或 localhost return-url，模拟支付入口已默认禁用并在 `prod-split` 固定关闭，旧 `/api/payment/pay` 也不再引导演示模拟支付，支付/通知通用模块和支付确认服务不再暴露沙盒或 mock 口径；`java-notification` 旧短信/邮件直发入口也已默认禁用。`grab-service` 运行时代码不再静默回退本地服务 URL、数据库、Redis、RabbitMQ 或监听地址；frontend server proxy 不再在缺少 `API_PROXY_TARGET` 时回退本机 Gateway；首页不再在 API 失败时展示 mock 分类、mock 分区或 fake banner。Compose 已拆出本地入口与生产示例模板边界。PostHog SDK transport 已在用户授权后接入，并完成 disabled 态无外部请求验收。真实部署环境变量注入清单已补齐并纳入静态守护；Sentry 真实 DSN 启用态验收和 PostHog 真实 token/host 项目侧验收已按用户确认后置到生产运维上线前补充，不再阻塞当前本地生产前收口。剩余部署风险主要是生产运维阶段外部 SaaS enabled 验收和 Alipay sandbox 同意退款链路稳定性。
